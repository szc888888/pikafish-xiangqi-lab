# 长棋谱整局复盘

用户反馈：棋谱超过 120 个半回合后，前端禁止整局复盘。旧 `ReviewRequest` 同样限制为 120，单次顺序分析所有局面，不能只删除前端限制。

## 实现

- 支持最多 400 个半回合，与现有行棋接口的历史上限一致。
- 120 个半回合以内保留原接口及云端快照持久化合同；更长棋谱每批分析 30 个半回合，顺序发送并合并整局结果。
- 新接口 `/api/engine/review/segment` 接收原始 FEN、从第一步开始的完整前缀、绝对 `start_ply`。每批最多新增 30 步，前缀总长最多 400。复用 `validate_history`，保留跨批长将、长捉校验；复用同一个引擎及其并发协调机制。
- 复盘期间冻结棋谱，按绝对半回合编号展示进度。旧会话失效后不再发起后续批次；中途失败不返回部分成功结果。规则违规时保留合法前缀及明确停止原因。
- 弹窗和逐步复盘入口均复用现有浏览器复盘缓存。初版长棋谱仅存浏览器；后续已按 [云端存档方案](2026-11-16-cloud-long-review.md) 接入现有数据库，登录且隐私同意有效时支持保存与恢复。教练追问同步支持 400 个半回合。
- 不修改棋规、数据库模型、迁移、正式赛果或战绩。

## 验证记录（macOS）

环境：Darwin、zsh、Python 3.11.12（项目 `.venv`）、Node.js 22.16.0、npm 10.9.2。

- 后端 `apps/api/.venv/bin/python -m pytest -q -rs`（在 `apps/api` 使用 `.venv/bin/python`）：194 通过、3 跳过；跳过均为需要 Windows / PowerShell 的启动脚本运行测试。之后新增容量错误回归用例，定向 `.venv/bin/python -m pytest -q -rs tests/test_review_segments.py`：6 通过。未验证 Windows / Linux。
- 前端在 `apps/web` 执行 `npm test`：27 个文件、120 项测试通过，0 失败、0 跳过；`npm run build`：通过。
- 根目录 `./start.sh --dry-run`：通过，API 命令保留 `--workers 1`。
- 回归覆盖：132 步棋谱及绝对编号、原始前缀传递、跨批长捉、非法着法、批次与总长度边界、教练长历史、引擎容量和排队超时错误、合并与停止、失败不冒充完成、过期进度、两种复盘入口缓存、复盘不修改对局。
- 只重启本机 API，继续使用 `--workers 1`；网页服务进程未重启。实际 HTTP / Pikafish 验证 132 个半回合：5 批全部完成、编号连续、共 132 个结果，耗时 40.03 秒（用于连通性验证的 depth=1、movetime_ms=1，不代表默认复盘速度）；API / 引擎健康、网页 HTTP 200。

代码审查发现并修复：逐步复盘入口的长棋谱缓存遗漏；分段接口的容量错误缺少结构化错误码。
