# 长棋谱复盘云端存档

用户已授权完善长棋谱复盘的数据库保存。复用现有 Review / ReviewItem 表，不新增或修改数据库模型，不需要迁移。

1. 先补接口及前端回归测试：长棋谱完整存档、分段失败恢复、重复请求、跨账号及隐私拒绝、删除与导出、刷新或换浏览器读取结果。
2. 登录且隐私同意有效时，通过现有棋局所有权校验创建服务端复盘快照。复盘状态使用现有 status，分段进度及最终分值保存在 parameters 的版本化元数据中；服务端每次读取自己的原始快照并分析下一批最多 30 个半回合，客户端不能上传评估结果。
3. 每批引擎分析成功后一次事务保存结果和进度，未完成标为 in_progress，最后一批完成才标 complete。重复已完成批次返回已保存进度；失败重试从数据库记录的进度继续。单 worker 内防止同一复盘并行推进；计算后重新检查账号、同意、棋局和复盘是否仍存在，避免删除后的数据回写。
4. 前端长棋谱 persistReview 改用上述流程；游客仍使用原来的无账号分段接口。相同棋谱和参数优先恢复云端进度或读取完整结果；主动“重新生成”创建新的复盘。完整结果仍缓存本地；云端保存失败应显示错误，不能冒充已保存。
5. 沿用账号隔离、隐私同意、导出、删除接口。用真实保存及读取流程验证，运行 macOS 后端测试、前端 npm test / npm run build，并启用本机新 API。

验收：132 个半回合能在清空本地缓存后从同一账号云端读取全部结果；失败和重试不会重复插入结果，也不会把未完成局标为 complete；游客和其他账号不能访问；删除后不能推进或读取；导出包含所有结果。

## 实现与验证

- `app/cloud_review.py` 复用现有表；`POST /api/games/{id}/reviews/segmented` 创建或读取存档，`POST /api/reviews/{id}/advance` 推进最多 30 个半回合。输入仅包含棋谱、参数和期望进度，评分及结果均由服务端引擎生成。
- 长棋谱仅本地保存的旧缓存在用户具备云端保存条件后会重新接入服务端存档；本地练习局沿用现有导入接口，保留 `origin=guest_import`、`counts_for_stats=false`，不影响正式战绩。复盘失败重试恢复进度，主动重新生成建立新记录。
- macOS Darwin / zsh；Python 3.11.12（项目虚拟环境）、Node.js 22.16.0、npm 10.9.2。
- `apps/api`：`.venv/bin/python -m pytest -q -rs` → **202 passed, 3 skipped**，无失败。跳过均为 `tests/test_start_dev_script.py` 中需要 Windows / PowerShell 的运行测试；依赖产生两条弃用警告。未验证 Windows / Linux。
- `apps/web`：`npm test` → **126 passed**，27 个测试文件，无失败或跳过；`npm run build` → 通过。
- 根目录 `./start.sh --dry-run`、`git diff --check` → 通过。
- 真实引擎 / HTTP / SQLite 联调使用临时隔离库与单 worker API：132 个半回合逐批保存；第 30 个半回合后重启测试 API，恢复同一复盘进度并完成全部 132 项；新的客户端请求读回相同完整结果，数据库实际行数为 132。测试结束清理临时服务和数据库，未向用户数据库写入测试棋局。
- 账号隔离、隐私拒绝、搜索期间删除账号/棋局或隐私失效、重复请求、并发推进、失败不写部分批次、导出、删除后禁止读取均有回归覆盖。
- 本机 API 已重启并保留 `--workers 1`；健康检查 API / 引擎均就绪，OpenAPI 确认新接口已加载，网页返回 HTTP 200。未重启网页服务。
