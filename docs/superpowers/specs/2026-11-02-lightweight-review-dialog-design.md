# 轻量 AI 陪练复盘弹窗设计

## 目标

让用户在对弈中随时复盘当前已完成的棋谱，并在对局结束后轻松找到值得学习的时刻。复盘不得改变棋局、棋谱或当前行棋状态。

## 用户流程

- 对弈页面提供“复盘”按钮；摆棋中、引擎思考中、尚无着法或棋谱超过复盘接口上限时不可用，并明确说明原因。
- 点击后冻结当前起始 FEN、走法列表和当前棋局版本作为分析快照。用户可继续查看弹窗中的加载状态；若分析期间棋局继续变化，结果标记为“基于旧快照”，不能覆盖实时棋盘或自动改变选中局面。
- 复盘结果在模态窗口中展示。窗口包含局面棋盘、最多三个关键时刻、每个时刻的一句话说明和引擎推荐着法；不足三个时不补足。点击时刻只切换弹窗内棋盘局面。
- 关键时刻优先选择用户执棋方的 `blunder`、`mistake`、`inaccuracy`，按严重程度和损失排序；用户执棋方不足三项时，再补充对手方最值得学习的时刻。相同半回合只出现一次。
- 用户可以从关键时刻进入现有 AI 教练问答，并携带对应局面和引擎复盘上下文。关闭窗口后回到当前实时棋盘与对局状态。
- 引擎不可用或请求失败时在窗口内显示可读错误及重试入口；不丢弃当前对局，也不把部分结果伪装成完整复盘。

## 触发与终局

- 首版保留“手动点击复盘”的明确入口；对局结束时自动生成复盘摘要，但只在规则层确认将死或困毙后触发。手动落子和引擎应手后的终局都使用同一规则判定，不使用引擎 cp、mate 或胜率代替终局判断。
- 自动摘要失败不阻塞结束提示；用户仍可在对弈页使用复盘按钮重试。
- 尚无走法时不请求复盘；棋谱超过 120 个半回合时保留当前对局并提示先分段复盘。

## 规则与数据边界

- 复用现有后端 `review_game`、规则历史校验和引擎候选过滤；引擎只提供评估和建议，不作规则裁判。
- 请求使用点击时捕获的 `initial_fen + moves` 快照，不使用弹窗打开后可能变化的实时状态。非法棋谱按现有接口错误处理。
- 只纳入存在合法引擎推荐着法的复盘项目。将杀比较无可靠 cp 损失时，不显示 cp 数值；不得把 mate 转换成普通损失分。
- 解释首版使用基于复盘标签、走法及引擎推荐的简短模板，不要求大模型在线；追问才调用已有 AI 教练接口，并明确区分引擎评估与教学解释。
- 不新增棋局存档字段或数据库迁移。当前棋局若已持久化，仍沿用现有持久化复盘路径。

## 界面与状态

- 在对弈操作区增加“复盘”入口，运行时对局也可使用；按钮状态反映摆棋、引擎思考、无走法、超长棋谱和引擎未配置等原因。
- 使用响应式模态窗口承载复盘视图，桌面端并排显示棋盘和关键时刻，窄屏纵向排列。支持关闭按钮、遮罩点击关闭和 Escape 关闭。
- 复盘棋盘浏览状态、弹窗选中时刻和 AI 追问上下文均独立于主棋盘浏览状态，关闭后不需要恢复性写入。
- 关闭窗口不取消已经完成的分析结果；重试时捕获新的当前快照。

## 验证

- 前端测试覆盖复盘按钮可用性边界、关键时刻筛选/排序、旧快照结果，以及弹窗选择不改变实时对局状态。
- 后端继续使用现有复盘和规则测试，补充关键时刻选择单元测试，覆盖少于三项、评分并列、mate 无 cp、无推荐着法及棋规停止情况。
- 交付前运行 API 测试、Web 测试和 Web 生产构建，并做桌面与窄屏弹窗视觉检查。
