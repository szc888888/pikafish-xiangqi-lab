# 微信小程序 V1 设计

首版提供「进入棋友大厅 → 选 AI 棋友和执棋方 → 下完一盘 → 查看棋谱」。游客无需登录，棋局保存在当前设备。需要云端存档和正式战绩时，用户可登录微信并同意当前版本的隐私政策。Web 与微信共用 FastAPI、棋友目录、象棋规则、Pikafish 和账号数据生命周期。

## 技术选型与发布前置条件

普通微信小程序获准承载完整的人机象棋对局时，采用 uni-app Vue 3 + TypeScript，使用独立的 CLI 项目编译到 `mp-weixin`。现有 Web 组件使用浏览器布局和交互，微信端实现自己的触控棋盘，复用 API 类型、FEN/UCI 转换、棋子标签和棋谱格式等与平台无关的代码。若平台要求使用微信小游戏，则改用小游戏运行时实现界面和平台适配，复用同一后端与可移植 TS 模块。已有 H5 可继续作为独立入口，使用 `web-view` 仍须核验平台类目及业务域名条件。

在开始制作正式页面前，用实际发布主体在微信公众平台确认人机象棋的类目、普通小程序或小游戏形态、所需资质与备案。材料按实际功能填报，类目和主体以平台核验结果为准。可先用包含棋盘和真实对局流程的低成本技术样板做真机联调。[微信公众平台](https://mp.weixin.qq.com/) · [工信部 APP 备案通知](https://wap.miit.gov.cn/jgsj/xgj/wjfb/art/2023/art_dd783a581c9644a4aee10afa582811db.html) · [uni-app CLI](https://uniapp.dcloud.net.cn/worktile/CLI.html)

2026-11-19 从开发机用 `curl` 检查 `https://1237092oabk53.vicp.fun`，`/`、`/api/health`、`/api/ai-friends` 均返回 HTTP 200，TLS 校验通过，健康接口报告引擎就绪，目录版本 `v1` 返回 20 位棋友。用实际 AppID 将该主机配置为 `request` 合法域名，在 iOS 和 Android 开启域名校验后覆盖移动网络及 Wi-Fi。域名的备案、归属与微信后台准入仍待核验。若现地址不能加入合法域名，使用发布主体可管理并满足平台要求的正式 HTTPS API 域名，反代到现有 API。体验版和生产版的 API 地址分开配置，密钥只在服务端。[微信网络请求文档](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html)

## 页面与交互

| 页面 | 首版内容 |
| --- | --- |
| 棋友大厅 | 按休闲、练习、挑战筛选或随机匹配，点棋友后选择执红或执黑，显示最近可继续的对局。 |
| 对局 | 显示双方、当前行棋方、最后一步、将军和终局状态。点棋子再点目标交叉点。提供认输、返回大厅、重试当前回合。返回后可从记录继续，认输前二次确认。 |
| 对局结果 | 展示用户视角的胜负和与结束原因，支持重看棋谱和新开一局。每次重开创建新棋局 ID。 |
| 我的棋局 | 显示游客本地局与账号云端局，区分进行中、等待 AI、已结束。支持查看逐步棋谱、继续对局和删除，云端正式战绩来自现有统计接口。 |
| 账号与隐私 | 登录、隐私政策与同意、退出、导出、删除及撤销待处理的删除请求。 |

移动端保留 10 行 9 列、黑上红下的棋盘，执黑首手由 AI 走。底部操作区适配安全区域，棋盘交叉点坐标使用容器实测尺寸计算。棋子高亮可使用现有 TS 规则辅助，但只有后端校验通过的结果才能写入已确认棋谱。棋谱从起始 FEN 逐步重建，校验走法、当前局面和行棋方。首版功能边界为 AI 对弈、认输和逐步回看棋谱。悔棋、引擎评估、摆棋、图片识别、深度复盘和教练问答由后续版本评估，真人对弈、好友对弈和排行榜沿用项目 V1 边界。

## 目录与接口

```text
apps/miniprogram/src/
  pages/                 # 大厅、对局、结果、棋局、账号与隐私
  components/            # 棋盘、棋友卡片、回合状态
  features/hall/         # 对局和回合恢复流程
  platform/              # 微信请求、登录、本地存储与页面生命周期
packages/xiangqi-core/   # 从现有 Web TS 模块提取的可移植逻辑
packages/api-contracts/  # Web 和微信共用的类型
```

Web 中的 [`api.ts`](../../../apps/web/src/lib/api.ts) 使用浏览器 `fetch`、同源路径和 Cookie，小程序以 `uni.request` 封装绝对地址、超时与结构化错误，分开保留平台请求实现。后端规则来自 [`xiangqi.py`](../../../apps/api/app/xiangqi.py)，复用 [`game_hall.py`](../../../apps/api/app/game_hall.py) 的棋友应手、合法性复核和回合语义。需共享时提取共用函数，优先避开重写规则。

| 目的 | 接口 | 约定 |
| --- | --- | --- |
| 大厅 | `GET /api/ai-friends`、`POST /api/matches/recommend`、`POST /api/matches/random` | 直接复用公开接口，筛选值为 `casual`、`practice`、`challenge`。 |
| 正式开局 | `POST /api/hall/games` | 已登录且已同意隐私政策，提交 `opponent_id`、`user_side` 和可选 `name`。丢失响应后先查对局列表再引导用户继续或新开。 |
| 正式回合与恢复 | `POST /api/games/{id}/turns`、`GET /api/games/{id}` | 保留 `{turn_id, expected_version, user_uci}`。执黑开局 `user_uci: null`，返回棋局、用户着法、AI 着法及回合状态。 |
| 正式认输与赛果 | `POST /api/games/{id}/resign`、`GET /api/games/{id}/result`、`GET /api/me/game-stats` | 认输提交 `request_id`、`expected_version`，同一次认输重试使用原参数。 |
| 云端棋谱 | `GET /api/games`、`GET /api/games/{id}`、`DELETE /api/games/{id}` | 使用现有账号隔离和删除逻辑。体验版验证历史棋谱列表大小，必要时补充兼容的分页参数。 |
| 游客棋局 | 新增 `POST /api/hall/guest/games`、`POST /api/hall/guest/games/{id}/turns` | 对局和待提交回合保存在本机，服务端负责规则与 AI 应手。 |
| 微信会话 | 新增 `POST /auth/wechat/login`、`POST /auth/wechat/logout` | 微信授权码换项目会话，登出撤销当前微信会话。 |
| 账号与隐私 | `GET /api/privacy/config`、`POST /api/me/privacy-consent`、`GET /api/me`、`/api/me/exports`、`/api/me/deletion` 及现有子路径 | 复用隐私政策版本、数据导出、账号删除和撤销删除逻辑，真机验收导出文件可打开。 |

### 游客对局

正式开局接口依赖 `get_consented_user`。现在 Web 游客用 `/api/engine/move`，该接口可提交自定义引擎参数。小程序的游客入口按棋友 ID 选择目录中有效的五档之一，着法使用相同规则模块校验。

- 开局提交 `{opponent_id, user_side}`，服务端返回本局 ID、标准起始 FEN、行棋方、对手快照、配置版本及签名凭证。凭证绑定本局 ID、执棋方、起始 FEN、对手快照、棋谱摘要和协议版本。密钥轮换期间给现有凭证留验证窗口。游客记录保存在微信本地存储，带 `schema_version`、起始 FEN、当前局面、行棋方、UCI 历史、棋友快照、回合状态及凭证。
- 回合提交 `{guest_token, moves, turn_id, expected_version, user_uci}`。`moves` 是上一份已确认棋谱，游客版本定义为已确认着法数量。服务端验证签名、版本与棋谱摘要，并用规则模块重建棋局、校验轮次和用户着法。需要 AI 应手时搜索并校验候选。成功返回 `turn_id`、更新后的版本和签名凭证、完整棋谱、当前局面、行棋方及终局状态。请求参数只控制棋局和着法，搜索档位、预算、历史长度及流量上限由服务端约束。
- 发送前先保存当前快照与原始待提交请求。失败或杀进程后，用原请求重试，期间锁定落子。服务端可重复搜索，客户端只接受仍对应当前棋局、版本、请求编号的第一份完整成功响应，再一次性替换本地记录。明确返回非法着法时清除待提交请求并回到已确认局面。无账号的请求不写正式棋局或正式战绩。
- 游客认输在本机写入结束状态。清理小程序存储会丢失游客棋谱，记录页须说明。已登录并同意隐私政策之后的新局才走正式接口，当前游客局仍可在本机继续。首版将游客棋局导入与 Web 账号绑定排在后续阶段。若开启导入，必须复用 `/api/games/import`，保留 `origin=guest_import`、`counts_for_stats=false`，对认输等无法从棋谱重建的赛果单独设计兼容方案。

### 正式回合与弃局

发送前保存云端棋局 ID 和原始请求。AI 失败时用户步可能已落库，此时棋局为 `awaiting_ai`，回合为 `ai_pending`。重启、回到前台、请求超时或收到 `409` 时，先读取棋局详情。若服务端已有待处理回合，按 `pending_turn_id`、`pending_turn_expected_version`、`pending_turn_user_uci` 恢复原请求。`expected_version` 取原回合版本，不能用当前棋局版本替换。若本地有请求但服务端暂无待处理回合，可用旧请求查询幂等结果，收到 `stale_game` 或冲突后以最新棋局为准，提示用户重新选择。版本和棋局 ID 较旧的响应丢弃。

`429 queue_full` 或排队超时提示稍后重试同一回合，进棋盘后提供一个重试入口。状态明确前禁止继续落子。服务器拒绝非法着法时显示具体规则原因。正式赛果只来自项目已有的将死、困毙、规则性和棋或主动认输。退出、断网和未完成均保留为可继续的棋局，不触发超时判负。

### 微信账号与隐私

用户点击「使用微信登录」后调用 `wx.login`，小程序提交一次性 `code`。后端用配置的 AppID 和 AppSecret 调用 `code2Session`，按 `(issuer="wechat:<appid>", subject=openid)` 查询或建立 `UserIdentity`，沿用 `User` 和现有唯一键。AppSecret、`session_key` 和一次性 `code` 不写入客户端会话或应用日志。首版只取登录所需身份。同一 AppID 再次登录返回同一项目用户，既有邮箱或 OIDC 账号需要经过独立的绑定流程才能共享棋谱。[微信登录文档](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/login.html)

用短期可撤销的不透明 Bearer 会话接入现有账号依赖，浏览器继续通过 Cookie。服务端存储令牌摘要、用户 ID、过期时间和签发时的 `session_version`，请求时检查过期、撤销、用户可用状态和会话版本。账号删除请求与撤销沿用现有账号状态权限。客户端仅保存自己的会话令牌，退出或切换账号清空云端数据及在途请求上下文。过期后引导重新登录；确认仍是同一账号并拉取云端棋局后，再恢复待处理请求。若新增会话表，须新增 Alembic 迁移并沿用账号清理机制。

登录授权与云端存档的隐私同意独立处理。以 `/api/privacy/config` 和 `/api/me` 为准展示当前政策、判断同意是否有效。拒绝或版本更新后仍可使用本机游客对局。隐私保护指引所列数据、用途和删除路径须与实际行为一致，包含账号身份和云端棋谱用途。

## 开发顺序与验收

1. **核对平台形态和域名。** 用实际 AppID 确认类目和发布材料。配置合法域名并用真机请求健康、目录接口，确定体验环境与生产入口。核验期间可继续细化纯 TS 模块及 HTTP 合同。
2. **跑通游客对局。** 提取可复用的坐标和规则适配，新增游客小程序入口。实现大厅、触控棋盘、执黑开局、弱网恢复、本地续局和棋谱回看。先实现规则和契约测试，再接界面。
3. **接入微信账号与正式局。** 实现微信会话、隐私同意、云端开局、重试、统计与数据生命周期。服务端和 Web 共用账号鉴权及正式局规则。涉及模型改动时，在隔离库先检查实际 Alembic head、备份并完成 upgrade/downgrade/upgrade，再安排目标环境迁移。
4. **真机及生产前验收。** iOS 和 Android 各完成执红、执黑、终局、认输、退出续局和弱网重试。用两个账号验证棋谱隔离，测试政策变更、全链路导出与删除。发体验版后再按已核定类目提审。

同一 Uvicorn worker 共享一个 Pikafish 进程，生产继续显式配置 `--workers 1`。游客与正式局使用同一引擎协调机制，最多一个搜索、两个排队，排队上限五秒。并发验收包含第四个请求的结构化限流、排队超时以及错误后的会话恢复。记录请求 ID、排队与应手耗时、错误码和恢复结果，用于判断现部署是否适合扩大体验版范围。

| 验收层 | 应覆盖的结果 |
| --- | --- |
| 规则与接口 | 用户和 AI 的非法着法均被拦截，覆盖将帅照面、自陷被将、长将、长捉、普通重复、困毙和将死。棋谱和当前局面可重建，旧格式兼容，未完成局不进正式战绩。 |
| 恢复与鉴权 | 重复点击、丢失响应、进程结束、相同回合重试和账号切换不会多走一步或串号。伪造游客凭证、越权棋局读取、会话过期和未同意隐私政策均验证拒绝路径。 |
| 工程检查 | 后端按目标平台运行项目约定的 pytest 全量与大厅定向检查，Web 运行 `npm test`、`npm run build`，新增小程序运行自身测试和 `npm run build:mp-weixin`。报告实际命令、平台与通过、失败、跳过结果。 |
| 发布检查 | 开启合法域名校验的 iOS、Android 真机能下完一盘。按部署平台做实际启停和引擎搜索，验证现有 Web 在并行小程序请求下仍可使用。 |
