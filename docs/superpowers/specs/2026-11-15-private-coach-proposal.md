# 私教数据功能分析与建议范围（待确认）

日期：2026-11-15。状态：方案草案，未实施产品功能。

## 目标与边界

参考用户截图的私教数据总览、六维能力图、专项入口和对局精解，建设基于真实棋谱的个人复盘数据模块。截图只能确认页面包含这些入口，无法得知原产品内部算法、收费策略或指标口径；以下为本项目的建议设计。

本项目 AGENTS.md 将能力画像、个性化训练和动态评级列为后续版本，因此建议作为 V2 独立增量，保留 V1 棋友大厅作为首页。截图中的立即激活与付费锁不作为本次需求；不默认引入订阅或支付。

## 已有能力（直接检查源码）

- `apps/api/app/review.py`：按棋谱逐步调用现有引擎，输出用户走法、最佳走法、cp 损失和失误等级。将杀变化单独处理，不能换算为普通 cp。
- `apps/api/app/persistence.py`：已有棋局、用户执棋方、AI 对手快照、正式统计资格，以及带棋谱快照、哈希和引擎参数的复盘及逐步明细模型。
- `apps/web/src/lib/reviewSummary.ts`：已有关键时刻筛选、分值解释和整局复盘限制提示。
- `apps/web/src/components/ReviewDialog.vue`、`apps/web/src/lib/useReviewSession.ts`：已有轻量复盘与问答流程，可作为专项数据的回看目的地。
- `apps/api/app/openings.py`：已有小型开局线路前缀匹配，未命中不能解释为开局走错。
- `apps/web/src/lib/gameEvents.ts`：已有提示与悔棋事件，不能据此推断心理状态。
- 当前走法模型虽有落库时间，但公开走法响应没有有效思考耗时字段；落库间隔包含网络、引擎与离线时间，不能视为用户思考时长。

本仓库未发现现成的 graphify-out/graph.json，以上结论来自源码核对，不宣称经过知识图谱验证。

## 可选路线

1. 只复刻页面：最快，但不能完成真实数据产品，不推荐作为交付目标。
2. 先做真实复盘数据版（推荐）：总览、阶段统计、关键失误、将杀相关记录和对局精解；缺失维度明确显示数据不足。
3. 完整教练系统：在路线 2 后增加有效用时采集、训练题生成与校验、评级及真实人群基准。需要分阶段交付，不能凭截图推定算法。

## 推荐第一版

| 入口 | 提供的数据 | 口径限制 |
| --- | --- | --- |
| 开局 | 阶段内可评估着数、各级失误数、平均 cp 损失，已知开局匹配 | 阶段划分使用公开且版本化的产品启发式；不是象棋规则裁定；未匹配开局不扣分 |
| 中局 | 关键失误与推荐走法，点击返回对应局面 | 指标只统计用户一方；无法判断的着法不计入损失均值 |
| 残局 | 进入残局后的着法表现和失误分布 | 需先定义并测试材料与阶段划分；未进入残局显示无样本 |
| 将杀 | 引擎预测将杀出现与变化的关键着法 | 区分预测和规则终局；首版不宣传杀棋题正确率或完备的漏杀识别 |
| 用时 | 显示尚无有效用时数据 | 后续采集有效思考耗时；历史对局不回填虚构数值 |
| 心态 | 建议改为“对局稳定性”，后续提供优势波动等行为指标 | 不评价心理健康，不将悔棋、输棋直接判为心态差 |
| 对局精解 | 本局小结、关键转折、推荐变化与现有教练问答 | 规则事实、引擎评估与教学推断分别表达；模型不可用时仍可看确定性数据 |

第一版优先展示可解释的原始指标与样本数；六维图保留缺失状态，绝不将未知值填成零分，也不将不同单位的原始指标直接连成能力多边形。需要完整能力雷达图时，另行定义、版本化并校准归一化评分。可先提供各阶段失误率对比与个人历史趋势。

“同段位能力”暂不提供：目前没有经过验证的用户段位及人群基准。AI 五档是对手策略档位，不能用作用户 Elo 或段位。对比可使用用户自己的上一时段，标注双方样本数和复盘覆盖率。

## 数据和接口设计方向

- Vue 3 单页体系新增私教数据视图及入口，不引入新路由或框架。
- 新增只读个人统计服务，复用现有授权与隐私同意依赖。统计读取已有有效复盘，不在页面打开时自动对所有历史棋谱发起引擎搜索。
- 聚合按棋谱快照哈希去重；只采纳与当前棋谱一致的复盘，排除失败、过期及规则中止的复盘；保留未复盘与无法评估数量。
- 正式对局统计只使用已完成、具有正式统计资格且未删除的本账号棋局。游客、导入、旧格式及练习内容可在单独的个人练习视图展示，不能提升正式战绩。
- 按用户执棋方过滤；观战和缺少执棋方的旧记录不猜测归属。
- 聚合时记录指标版本、阶段口径、引擎分析参数和可评估样本数；引擎版本或参数不一致的记录不能悄悄当作完全可比数据。
- 第一阶段尽量派生统计，避免新增画像缓存表。任何必要模型变化须新增 Alembic 迁移，并按项目规范完成隔离库演练。
- 删除棋局后派生数据立即排除对应记录；不建立绕过已有导出、删除、账号隔离的第二套存储。
- 复盘继续复用单引擎协调机制及现有容量限制；保留当前每次最多 120 个半回合的限制与明确提示，不能把长棋谱静默截断后称为整局分析。

## 验收与验证方向

1. 每项统计能回到对应真实棋局和着法，并标明分母、单位与样本不足。
2. 红黑视角正确；cp 和 mate 不混算；无有效 cp 时均值返回空值。
3. 覆盖空账号、无复盘、重复复盘、过期复盘、规则中止、引擎失败、缺少执棋方及旧存档。
4. 验证账号隔离、隐私同意、删除后统计变化、游客导入不增加正式战绩。
5. 验证阶段边界、黑方用户、无残局样本和将杀变化，所有推荐着法继续服从现有规则层。
6. 完成适用后端测试、前端测试及生产构建，按实际操作系统报告命令、通过/失败/跳过数量；本轮仅分析源码，尚未运行产品验证或声称功能完成。

## 待用户确认的范围

建议确认路线 2，作为 V2 的真实复盘数据首版；暂不加入收费激活、用户评级与同段位基准，缺少用时及稳定性数据时明确显示未采集。确认后再细化阶段口径、接口合同与实施计划。
