# 微信小游戏 V1 设计

日期：2026-11-19。状态：修订方案，供开发前评审。本次只更新设计，尚未创建小游戏工程、修改后端或执行数据库迁移。

## 1. 产品范围

发布形态已由用户确定为微信小游戏，类目为棋牌。用户截图显示正在填写小游戏备案的游戏内容，不能据此认定备案、资质审核或发布已通过。

首版流程为「进入大厅 → 完成必要登录与准入 → 选 AI 棋友和执棋方 → 对局 → 结果与棋谱 → 继续未完成对局」。20 位 AI 棋友、五档策略、规则、引擎及账号数据生命周期复用现有服务。小游戏新对局使用云端回合记录；本地仅保存账号范围内的缓存和待发送命令。

首版实现棋友筛选与随机选择、执红/执黑、合法落子、将军提示、认输、断线重连、棋局列表、逐步棋谱回看、正式战绩、隐私政策及数据删除/导出。悔棋、真人/好友对弈、排行榜、支付、广告、聊天、图片识别、摆棋、教练及自动深度复盘留到后续版本评估。Web 原有功能保持独立，小游戏范围不等于 Web 功能下线。

## 2. 技术选型

**建议主路线：TypeScript + 微信小游戏 Canvas 2D + 轻量构建工具，通过微信开发者工具调试和上传。** 首版主要为固定二维棋盘和有限列表/弹层，采用原生小游戏平台接口，减少外部引擎和编辑器依赖。此为工程判断，实际启动、中文字体、列表和触控表现须由早期真机样板验证。

| 方案 | 取舍 |
| --- | --- |
| 原生小游戏 Canvas 2D + TypeScript | 推荐。棋盘绘制直接，纯 TS 可复用；需自己实现按钮命中、列表滚动、弹层、文本换行，并验证无障碍限制。 |
| Cocos Creator + TypeScript | 备选。场景、动画、UI 编辑和资源管理完善，增加引擎与编辑器依赖。若原生 UI 样板成本过高，先评审改选再进入完整界面开发。[官方微信小游戏发布说明](https://docs.cocos.com/creator/3.8/manual/zh/editor/publish/publish-wechatgame.html) |
| uni-app 普通小程序 | 不作为小游戏客户端。原 `mp-weixin` 页面方案废止，Vue 页面布局不直接迁移。 |

拟用 esbuild 打包 TS，单独执行 TS 类型检查，Vitest 测试平台无关逻辑。具体版本在建立工程时固定并提交锁文件。小游戏产物包含 `game.js`、`game.json` 与开发者工具配置；`npm run build:wechat` 为拟新增脚本，当前不存在。正式配置使用小游戏 AppID，AppSecret 不进入产物。

架构为「Canvas 场景与输入 → 对局状态机 → 平台请求/存储适配 → HTTPS FastAPI → 现有规则与大厅服务 → 单一 Pikafish」。引擎留在服务器，客户端不下载 Pikafish 或 NNUE。

## 3. 发布准入、登录与隐私

联网象棋按网络游戏方向准备实名、防沉迷与发布材料。国家新闻出版署的说明明确涉及网络游戏实名和游客体验模式，本修订据此删除匿名联网对局和原设计的游客签名回合接口。[国家新闻出版署说明](https://www.nppa.gov.cn/xxgk/zcjd/202108/t20210830_4759.html)

小游戏 AppID、发布主体、棋牌子类、游戏出版/运营相关资质、小游戏备案及平台实名防沉迷接入方式，由发布主体按实际后台要求核实。小游戏备案、域名备案与游戏资质是不同事项，当前截图不证明全部完成。[工信部 APP 备案通知](https://wap.miit.gov.cn/jgsj/xgj/wjfb/art/2023/art_dd783a581c9644a4aee10afa582811db.html)

用户可先浏览产品说明、隐私政策和棋友介绍。新开及继续网络对局前检查：项目会话有效、隐私同意有效、账号可用、游戏准入有效。`wx.login` 获取临时代码，由后端交换微信身份；`openid` 是身份标识，不等于实名通过。优先使用平台实名防沉迷能力，自身不另建身份证采集表单。

服务端定义 `GameAccessProvider` 接入边界，输出 `allowed/blocked/unknown`、有效期及适用原因，验证平台认可的证据。客户端传入的布尔值和未验证的回调不能放行。具体 SDK、验证方式和限制中断流程在阶段 0 用实际 AppID 核实；未配置、未知或验证失败时禁止新建/继续网络对局。开发可使用显式测试适配器，生产启动拒绝测试适配器。不能为了做界面而假设准入接口已存在。

平台要求停止游戏时锁定着法；服务端在搜索前及写入 AI 着法前检查准入。搜索中准入失效时不再推进棋局，已经合法提交的用户步保留为 `awaiting_ai`，具备资格后恢复同一回合。限制、退出和异常均不判负。拒绝或更新隐私政策后，可浏览说明和执行既有账号数据权利，不以匿名网络对局绕过。缓存棋谱显示也须符合平台实际限制。

## 4. 场景与触控

竖屏，浅色背景、木色棋盘、红黑棋子。大厅为可滚动棋友卡片，顶部展示继续对局，支持休闲/练习/挑战筛选。选择棋友后弹出执红/执黑与开始按钮。对局顶部显示棋友及行棋状态，中部棋盘，底部显示用户和操作区。结果以弹层展示，保留棋盘背景。

| 场景 | 内容 |
| --- | --- |
| 启动与准入 | 最小资源载入、会话和准入检查、错误重试及必要的用户操作入口。 |
| 大厅 | 20 位 AI 棋友、筛选、随机选择、最近未完成局；推荐只按体验分类。 |
| 对局 | 选子、合法目标、最近一步、行棋方、将军、认输、返回及失败重试。 |
| 结果 | 用户视角胜负和、结束原因、回看、新开一局。 |
| 棋局和棋谱 | 查看云端历史，继续未完成局，从起始 FEN 前后逐步回看；回看不修改正式局。 |
| 账号与设置 | 隐私、静音、退出、导出、单局删除、账号删除及撤销待处理删除。 |

棋盘恒为 10 行 9 列、黑上红下，执黑也保持逻辑和显示方向，首版不翻转。坐标使用现有 FEN/UCI 转换，Canvas 按实际安全区域、可用尺寸和像素比布局。输入坐标与绘制统一换算，按最近交叉点且在命中半径内判断落点。边缘、河界、九宫和不同屏幕纳入验证。

触摸移动超过滚动阈值后取消点击，弹层拦截底层触摸，每次只接受主触点的一次落子。可切换己方选中棋子，无效落点显示具体原因。服务器确认前仅显示临时效果，不能写已确认棋谱或提交下一步。高亮复用 TS 规则；规则不一致时加载服务器棋局并记录差异，最终由后端判断。认输二次确认，等待恢复回合期间不发送认输。返回大厅保留对局，已结束棋局禁止落子。

帮助、隐私与长棋谱需要可滚动文本。阶段 1 先验证中文换行、字体、滚动和屏幕阅读可达性限制。首屏棋盘、棋子与必要 UI 随包，资源按场景加载，避免远程字体或图片成为开局依赖。静止时按状态变化重绘，动画才按帧更新；后台暂停绘制与音效。包体限制和最低基础库以实际工具规则及样板验证后固定。

## 5. 代码结构与共享

```text
apps/wechat-game/
  src/main.ts
  src/scenes/          # 大厅、对局、棋谱、设置和准入
  src/render/          # 棋盘、文本、列表、弹层和命中检测
  src/features/hall/   # 对局状态机、命令重试与恢复
  src/platform/       # 请求、会话、存储、准入和生命周期
  assets/
  project.config.json
  game.json
packages/xiangqi-core/ # 从现有 TS 提取的可移植逻辑
packages/api-contracts/ # 实际使用的共享合同类型
```

以上是目标目录，当前未建立。按需从 [`xiangqi.ts`](../../../apps/web/src/lib/xiangqi.ts) 提取棋盘类型、FEN/UCI、合法目标和棋谱格式，保持 Web 回归。类型以 Pydantic 合同为准，只共享大厅所需子集。共享模块不依赖 Vue、DOM、`window`、`localStorage`、微信 API 或 Canvas。

请求适配使用 `wx.request` 与绝对地址，处理 Bearer、请求 ID、超时、结构化错误和取消。场景销毁移除订阅；迟到响应必须匹配账号、棋局、命令、版本和当前状态才能更新界面。取消客户端请求不代表服务器回滚用户步。

本地按环境、AppID、用户 ID 分命名空间。保存 `schema_version`、最近棋局 ID、有界棋谱缓存及发送前持久化的开局/回合/认输命令。单个棋局检查点存为一个对象，包含版本与校验信息；损坏时从服务器恢复。持久化失败则不发送新命令，提示存储异常。清理缓存后可登录找回云端局；退出清理令牌、私有缓存和在途上下文，下次登录先从服务器查询。

## 6. 接口与身份

复用 [`main.py`](../../../apps/api/app/main.py)、[`models.py`](../../../apps/api/app/models.py)、[`auth.py`](../../../apps/api/app/auth.py)、[`game_hall.py`](../../../apps/api/app/game_hall.py) 和 [`xiangqi.py`](../../../apps/api/app/xiangqi.py)。Web 继续 Cookie 登录，小游戏增加不透明 Bearer，会话接入现有账号及隐私依赖。同一请求同时带 Cookie/Bearer 时不混合身份，账号冲突拒绝；非法 Bearer 不能回退 Cookie 成功。

| 合同 | 约定 |
| --- | --- |
| 现有大厅 | `GET /api/ai-friends`、`POST /api/matches/recommend`、`POST /api/matches/random`，筛选值沿用 `casual/practice/challenge`。 |
| 新增微信会话 | `POST /auth/wechat/login` 以临时 `code` 换项目令牌与有效期；`POST /auth/wechat/logout` 撤销当前会话。 |
| 新增准入查询 | `GET /api/wechat/game-access` 返回已验证状态与有效期；写入和搜索仍独立检查准入。 |
| 扩展正式开局 | `POST /api/hall/games` 沿用 `opponent_id/user_side/name`，小游戏新增 `Idempotency-Key` 头。 |
| 现有回合 | `POST /api/games/{id}/turns` 沿用 `turn_id/expected_version/user_uci`；执黑首手为 `user_uci: null`。 |
| 现有恢复/认输 | `GET /api/games/{id}`、`POST /api/games/{id}/resign`；认输沿用 `request_id/expected_version`。 |
| 现有记录/统计 | `GET /api/games`、`GET /api/games/{id}/result`、`GET /api/me/game-stats`、`DELETE /api/games/{id}`。 |
| 现有账号生命周期 | `/api/me`、`/api/privacy/config`、`/api/me/privacy-consent`、`/api/me/exports` 及状态/下载路径、`/api/me/deletion` 及取消路径。 |

小游戏不调用可传任意搜索参数的普通引擎接口，AI 参数由服务端棋友快照确定。Web 游客与导入继续遵循现有约束，导入不增加正式战绩；小游戏首版不提供游客导入和微信与邮箱/OIDC 账号绑定，不按显示名合并账号。历史列表先用现有接口，阶段 2 测量长列表成本，必要时以兼容参数扩展分页，不能直接修改返回类型导致 Web 失效。

微信身份用 `(issuer=wechat:<AppID>, subject=openid)` 复用 `UserIdentity` 唯一键，处理并发首次登录。AppID/AppSecret 来自服务端配置，`session_key`、登录临时代码、令牌与身份证信息不进应用日志或导出包。

新增会话表存高熵令牌摘要、用户 ID、会话版本、签发/过期/撤销时间。建议首版绝对有效期 24 小时，不设刷新令牌；过期后重新微信登录。每次鉴权检查账号状态及 `session_version`。待删除账号可获得受限会话进入 `/api/me` 和撤销删除流程，不能继续对局。永久删除及会话清理复用既有生命周期，账号版本递增使旧小游戏会话同样失效。

登录不自动同意隐私政策，政策版本沿用现有服务。导出仍生成既有 ZIP，通过携带 Authorization 头的文件下载适配交付；令牌不进入 URL。ZIP 的取得、解压和查看/分享须真机验证，不能假设文档预览接口可以直接打开 ZIP。若不可完成，发布前补齐同一生命周期内的安全交付方式。头像、手机号等与本版无关的信息不主动索取。

## 7. 幂等与恢复

当前开局接口没有幂等键。新增按 `(user_id, operation, idempotency_key)` 唯一的命令记录，保存规范化请求指纹及所创建棋局 ID，与棋局创建同事务提交并处理唯一约束竞争。同键同参数返回同一棋局，异参数返回 `409 idempotency_conflict`。小游戏必传开局键，Web 旧客户端无该头保持兼容；服务端根据已验证会话识别来源，不信任任意客户端来源头。单局软删除后，命令记录保留键、指纹和失效状态，同键返回不可恢复错误而非重建；永久删除账号时按生命周期一并清理。新开一局用新键，网络重试用原键。

回合和认输复用现有 `GameTurn`、指纹和唯一约束，避免重复搜索/重复提交形成两份下一局面。用户步保存后为 `awaiting_ai`，回合为 `ai_pending`。同一回合同参数取已有结果，异参数拒绝；AI 着法经规则过滤才落库。对局保存棋友 ID、目录版本与创建快照，后续改名或改策略不改变历史含义。

| 状态/事件 | 客户端行为 |
| --- | --- |
| 用户着法 | 持久化原始 `{turn_id, expected_version, user_uci}`，发送后锁定输入。 |
| 发送中/丢失响应 | 保留命令，拉取棋局确认，不自行撤销或判定完成。 |
| 等待 AI | 按 `pending_turn_id`、`pending_turn_expected_version`、`pending_turn_user_uci` 恢复，不能用增加后的棋局版本代替原回合版本。 |
| 重试返回已完成 | 使用返回的完整服务器棋谱，不再追加用户或 AI 步；可能返回当前更高版本棋局。 |
| `409 stale_game/turn_conflict` | 拉取服务器棋局，舍弃冲突临时效果，提示已恢复。 |
| `429 queue_full`、排队超时、`503 ai_pending` | 显示可重试错误，重试同一回合；自动补偿最多一次，随后手动重试。 |
| 会话/政策/准入失效 | 先完成对应步骤，确认同一用户并重新读取棋局，再恢复。 |
| 已结束 | 锁定棋盘，显示赛果，可回看或新开。 |

回到前台先查会话和准入再查询棋局。等待恢复期间可离开棋盘，禁止下一步或认输。正式赛果只来自将死、困毙、规则性和棋或用户认输。退出、后台、限时限制、网络失败、引擎异常和回看不产生赛果，V1 不实现超时判负。

## 8. 容量、部署与迁移

生产继续显式 `--workers 1`，所有客户端共享一个 Pikafish 和同一生命周期协调机制：一个搜索、两个排队，排队至多五秒，满载和超时返回结构化错误。取消、进程退出、非法候选和重置后恢复 UCI 会话。小游戏不提供远程引擎重置。容量不足先限制体验规模，多引擎工作池另行设计。

昂贵搜索和写入配置账号限速、总限速与单局在途约束，限制请求大小及历史长度。具体额度通过五档搜索与体验版压测确定。观察规则重建、排队和搜索耗时、满载率、恢复成功率与非法候选，不能把可创建多局当作可同时搜索多局。

2026-11-19 先前只读检查显示 `https://1237092oabk53.vicp.fun` 首页、健康及棋友目录均 HTTP 200，健康报告引擎就绪、目录 20 位；这只证明当时可达。实际小游戏 AppID 要验证请求/文件下载域名、TLS、归属与备案，在 iOS/Android 开启域名校验后测试移动网络和 Wi-Fi。必要时换正式 HTTPS API 域名反代现有服务。体验与生产配置、账号库隔离，不能把跳过校验当上线方案。

预计新增会话表、开局命令表；准入状态是否落库由实际验证机制决定。模型变更同步新增 Alembic 迁移。先核对实际 head、备份，在独立库完成 upgrade/downgrade/upgrade；不回改 `0007_ai_hall_v1.py` 或假设它是最新 head。新表加入账号隔离、导出、删除及清理：只导出会话元数据，不能导出可用凭据。旧字段默认值不能伪造对手、赛果、统计资格或准入通过。

## 11. 备案内容对齐与证据边界

场景描述与最终游戏一致：大厅选择 AI 棋友；二维九列十行棋盘，黑上红下，点击选子和目标走棋；轮流落子，显示行棋方与将军；结果显示胜负和原因，棋局列表查看棋谱及继续未完成局。玩法写标准象棋及项目明确的重复/长将长捉规则，背景为传统象棋益智对弈，系统功能只写已交付能力。不得把微信登录写成实名通过，或把尚未实现的聊天、真人对弈等写入材料。
