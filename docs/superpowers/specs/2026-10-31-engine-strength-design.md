# 引擎棋力档位与对弈体验设计

## 目标

在保留 Pikafish 作为规则和分析基准的前提下，为人机对弈提供用户可理解的五档对手水平。对弈可以受控地选择接近最佳的次优着法，分析、提示和复盘始终保持完整棋力。

## 用户界面

主界面显示“轻松陪练、入门练习、进阶对手、认真对弈、全力挑战”五档，不直接暴露深度、线程和 Hash。高级设置折叠后展示当前引擎（首版固定为 Pikafish）、是否允许次优着法、搜索深度、思考时间、CPU 线程、Hash 和提示候选数量。固定档位参数只读并注明由档位控制；只有切换为“自定义”后才允许编辑深度、思考时间、线程和 Hash，避免显示可改但不生效。关闭“允许次优着法”后，即使选择陪练档也始终执行最佳合法候选；该开关不改变当前对手档位对应的搜索预算。UI 线程上限使用浏览器可用逻辑处理器数，服务端仍负责最终边界校验。

提示改为“快速、标准、深入”，与对手水平相互独立。棋力档位是体验预设，不代表 Elo 等级分；各档搜索预算及可接受损失是首版启发式配置，文案不宣称有经过校准的棋力分数。

## 对弈行为

对弈接口独立于分析接口。后端请求 MultiPV 候选，复用现有引擎候选合法性和长将/长捉校验，在档位允许的评估损失范围内确定性选择候选。棋局 ID 与回合号参与选择种子，以便同一存档可重放。若最佳候选没有分值，则退回最佳合法候选；其他无分值候选不得参与弱化抽选。所有候选都缺少可比较分值时仍走最佳合法候选。分析、提示、复盘仍使用最佳着法接口。

固定档位线程数不得超过运行主机可用处理器数，必要时服务端自动降到可用上限，不因设备较弱而让档位返回 400。自定义档位仍校验实际线程数并返回具体参数错误。

## 数据与兼容性

新对弈请求携带 profile、game_id 和 ply；响应返回选中候选序号及种子。棋局持久化增加可空的 `engine_settings` JSON 字段，保存当前对手档位和自定义搜索参数；API 创建及走子接口接受可选设置，老客户端不传该字段仍可正常使用。固定档位只保存/返回对应的规范预设参数，避免旧参数让只读面板显示与实际搜索不符；自定义档位保留用户参数。Alembic 新增迁移，不重写既有棋谱。旧本地/云端棋局中缺少设置时统一按“进阶对手”及其预设值迁移；首次读取云端老棋局后将兼容默认值保存在本地，下一次走子时写入云端。提示速度仍是用户本地偏好，不纳入云端对局设置。

第一阶段不接入 Fairy-Stockfish 或 UCCI 引擎。

## 规则与验证

所有候选必须通过现有棋规校验；无法获得满足档位约束的候选时退回最佳合法着法。

## 验收标准

- 固定档位的参数在 UI 中不可编辑；自定义参数会实际到达引擎，深度/时间/线程/Hash 的请求值可通过接口测试验证。
- 次优着法开关会实际影响应手选择，并随本地设置和云端棋局存档保存；旧请求和旧存档默认开启以保持兼容。
- 固定档位在 1 核、2 核、4 核环境均能运行，线程设置不超过可用处理器数；自定义超出上限时返回清晰错误。
- 缺少分值的候选不会被陪练抽中；最佳候选缺少分值时确定性回退到最佳合法候选；全力挑战总选最佳合法候选。
- 云端棋局创建、追加走法和读取能够保留档位/自定义参数；迁移前的记录和旧客户端请求兼容并使用进阶对手默认值。
- 新增测试覆盖前端参数显隐/迁移、后端策略边界、API 参数透传与核心规则回归；全量后端测试、前端测试和生产构建通过。
- 档位棋力为首版启发式体验设置，不对外宣称具体等级分；后续若有足够对局反馈，再单独校准档位参数。
